# Workflow Walkthrough

This document walks through the `AgencyReport AI` n8n workflow node by node — what each one does, why it exists, and what its input/output looks like.

---

## Triggers

### `When clicking 'Execute workflow'`
Manual trigger used for testing and on-demand runs.

### `Weekly Schedule`
Schedule Trigger node configured to run automatically every Monday. Both triggers feed into the same first node (`Read Campaign Data`), so the workflow can be run manually or automatically without any duplicated logic.

---

## 1. Read Campaign Data
**Node type:** Google Sheets (OAuth2)
**Operation:** Get Row(s)

Reads all rows from the `campaign_data` sheet in the `AgencyReport AI - Campaign Data` spreadsheet. Each row represents one client's campaign performance for one platform and one reporting period.

---

## 2. Validate Data
**Node type:** Filter

Keeps only rows where:
- `client_name`, `platform`, and `reporting_period` are not empty
- `spend`, `clicks`, and `impressions` are numbers ≥ 0

Rows that fail any condition are routed to the "Discarded" output and excluded from the rest of the pipeline, preventing bad data from causing errors later.

---

## 3. Group by Client & Period
**Node type:** Code (JavaScript, run once for all items)

Groups all validated rows by `client_name + platform`. Within each group, rows are sorted by `reporting_period`; the most recent period becomes `current`, and the one before it becomes `previous`. Outputs one item per client/platform group (rather than one item per row).

---

## 4. Calculate Metrics & Comparison
**Node type:** Code (JavaScript, run once for all items)

For each group, calculates:
- **CTR** = clicks / impressions × 100
- **Conversion Rate** = conversions / clicks × 100
- **CPC** = spend / clicks
- **CPA** = spend / conversions
- **ROAS** = revenue / spend

All divisions use a `safeDiv()` helper that returns `0` instead of throwing or producing `Infinity`/`NaN` when the denominator is `0`. Also calculates percentage change for each metric between `current` and `previous` periods.

---

## 5. Prepare AI Input
**Node type:** Code (JavaScript, run once for all items)

Builds a structured text prompt containing only the real, calculated data for each group (spend, impressions, clicks, conversions, revenue, and all five metrics for both periods, plus percentage changes). The prompt explicitly instructs the AI: *"Use ONLY the data below. Do not invent numbers or results."* It also specifies the exact JSON response shape expected back.

---

## 6. Generate AI Insights
**Node type:** HTTP Request
**Endpoint:** `https://generativelanguage.googleapis.com/v1beta/models/gemini-3.6-flash:generateContent`
**Auth:** Query Auth credential (API key stored securely, never in the URL or JSON body)
**Retry on Fail:** 3 attempts, 2-second delay

Sends the prepared prompt to Google Gemini and receives back a structured JSON string (wrapped inside Gemini's standard response envelope) containing a performance summary, key wins, areas for attention, and recommendations — all grounded in the real metrics provided.

**Continue On Fail** is enabled here so that if one group's AI call fails even after retries, the rest of the batch still proceeds.

---

## 7. Parse AI Response
**Node type:** Code (JavaScript, run once for all items)

Extracts the raw text from Gemini's response (`candidates[0].content.parts[0].text`), strips any markdown code fences if present, and parses it into a real JSON object. Also pulls the original client/metrics data back in (referenced via `$('Prepare AI Input')`) since the HTTP Request node replaces the item data with Gemini's raw response. If parsing fails, a fallback object with a `parse_error` field is returned instead of crashing the workflow.

---

## 8. Generate HTML Report
**Node type:** Code (JavaScript, run once for all items)

Assembles a complete, responsive HTML document per group: a branded gradient header, a campaign overview section, a key metrics grid with color-coded trend arrows (green for improvement, red for decline — with cost metrics like CPC/CPA correctly treated as "improved" when they go down), and the AI-generated summary, wins, attention areas, and recommendations.

---

## 9a. Convert Report to File
**Node type:** Convert to File
**Format:** HTML

Converts the `report_html` string into a real binary `.html` file, primarily used for local preview/testing (downloading and opening the report directly in a browser) — not part of the client-delivery path.

## 9b. Store Report in Supabase
**Node type:** Supabase
**Operation:** Insert
**Table:** `reports`

Inserts one row per group into the `reports` table, storing `client_name`, `platform`, `campaign_name`, `reporting_period`, and the full `report_content` (HTML). `id` and `created_at` are auto-generated by the database.

---

## 10. Send Report Email
**Node type:** Gmail
**Operation:** Send
**Email Type:** HTML

Sends the report directly as an HTML email body to the client's inbox, with a subject line identifying the client and reporting period.

---

## Error Handler Workflow

A separate workflow, `AgencyReport AI - Error Handler`, is configured as this workflow's **Error Workflow** (set in Workflow Settings). It consists of:

1. **Error Trigger** — fires automatically whenever the main workflow fails
2. **Send a message** (Gmail) — emails an alert containing the workflow name, error message, and failure timestamp

This ensures failures are surfaced immediately rather than discovered later by a client not receiving their report.
